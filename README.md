# CIDR Squash

CIDR squash optimizes IPv4 addresses, CIDR networks, and address ranges. It outputs either
CIDRs (default) or IP ranges, with exact coverage or a bounded over-coverage budget.

CIDR squash оптимизирует списки IPv4-адресов, CIDR-сетей и IP-диапазонов. По умолчанию
выводит CIDR, а с `-r` - диапазоны вида `начало-конец`. В обоих режимах допускается точное
покрытие или небольшой контролируемый избыток адресов.

## Описание

С настройками по умолчанию результат точный: он покрывает тот же набор IPv4-адресов.
Необязательный лимит дополнительного покрытия позволяет включить небольшое число лишних
адресов в обмен на сокращение количества выходных записей. Исходные адреса никогда не
теряются.

Программа написана на C, не требует внешних библиотек при запуске, читает данные
из файла или stdin, выводит оптимизированный список в stdout, а статистику - в stderr.
Поэтому её удобно использовать в конвейерах командной строки.

## Разработка и проверка изменений

**Основные точки изменения:**

- `src/cidr_squash.c` - разбор IPv4, объединение интервалов и алгоритмы оптимизации CIDR/диапазонов;
- `tests/test_cidr.py` - проверки CIDR-режима;
- `tests/test_ranges.py` - проверки режима вывода диапазонов;
- `tests/test_properties.py` - проверки свойств покрытия;
- `tests/test_cli.py` - проверки интерфейса командной строки;
- `PKGBUILD` - сборка и установка пакета Arch Linux.

**Проверка изменений:** Ключевой инвариант алгоритма: результат всегда покрывает все входные IPv4-адреса; при `-p 0` покрытие точное, при `-p` избыток ограничен заданным бюджетом. После изменений запускайте все тесты из `tests/` и проверяйте оба формата вывода (`CIDR` и `-r`).

**Типовые изменения:**

- Формат ввода и ошибки разбора IPv4: изменяйте `src/cidr_squash.c` и
  сверяйте CLI-тесты в `tests/test_cli.py`.
- Алгоритм покрытия или вывод диапазонов: сверяйте `tests/test_cidr.py`,
  `tests/test_ranges.py` и `tests/test_properties.py`, а не один формат.

**Инвариант:** Выходные CIDR и диапазоны должны покрывать весь входной набор;
при `-p 0` не допускаются дополнительные адреса, при `-p` суммарный избыток
не должен превышать рассчитанный бюджет.

## Сборка

Проект использует `CMakePresets.json`. Для сборки через пресеты требуется CMake 3.25
или новее (версия схемы пресетов - 6).

```sh
cmake --preset release
cmake --build --preset release --parallel
```

Исполняемый файл:

```text
build/release/cidr-squash
```

Доступны также пресеты `debug`, `debug-asan` и `debug-msan`.

### Arch Linux: установка пакета через pacman

Для `PKGBUILD` необходимы `base-devel` и CMake:

```sh
sudo pacman -S --needed base-devel cmake
```

Выполнять из корня репозитория:

```sh
mkdir -p build/makepkg
BUILDDIR="$PWD/build/makepkg" makepkg -si
```

`BUILDDIR` обязателен: в проекте уже есть каталог `src/` с исходным кодом,
а `makepkg` по умолчанию использует каталог с таким же названием для своих
временных файлов. Каталог `build/` исключён через `.gitignore`.

`PKGBUILD` использует пресет `release` и собирает копию исходников, поэтому
рабочее дерево репозитория не затрагивается. Повторная сборка и обновление
пакета выполняются той же командой.

Проверка установленного пакета:

```sh
pacman -Qo /usr/bin/cidr-squash
```

Удаление пакета (при необходимости):

```sh
sudo pacman -R cidr-squash
```

### Ubuntu: сборка из исходников

Установить инструменты сборки (версия CMake должна быть не ниже 3.25):

```sh
sudo apt update
sudo apt install build-essential cmake
```

Затем из корня репозитория:

```sh
cmake --preset release
cmake --build --preset release --parallel
./build/release/cidr-squash -h
```

На Ubuntu это сборка исполняемого файла, **не установка DEB-пакета**.
Готовый бинарник можно запускать напрямую из `build/release/`.

## Использование

```text
Usage: cidr-squash [-r] [-p PERCENT] [-q] [FILE|-]

  -r, --ranges  Output start-end IPv4 ranges (default: CIDRs)
  -p PERCENT   Maximum additional coverage in percent (default: 0)
  -q           Suppress statistics on stderr
  -h           Show help
```

Каждая входная строка может содержать одиночный адрес, CIDR или диапазон:

```text
192.168.1.0/25
192.168.1.128/26
192.168.1.200-192.168.1.220
```

Допускаются пустые строки, комментарии с `#` и пробелы вокруг `-` у диапазонов.
Входные диапазоны должны быть записаны от меньшего адреса к большему.

### Вывод CIDR (по умолчанию)

Точный режим без дополнительного покрытия:

```sh
./build/release/cidr-squash direct.txt > direct_optimized.txt
```

Разрешить до `0.01%` дополнительных IPv4-адресов:

```sh
./build/release/cidr-squash -p 0.01 direct.txt > direct_optimized.txt
```

В CIDR-режиме сначала строится точное CIDR-покрытие, затем применяется жадное
объединение подсетей в пределах бюджета. Приближённый режим не гарантирует
глобально минимального количества CIDR.

### Вывод диапазонов

Точное объединение соседних диапазонов:

```sh
./build/release/cidr-squash -r direct.txt > ranges.txt
```

Приближённый режим, допускающий не более `5%` дополнительных адресов:

```sh
./build/release/cidr-squash --ranges -p 5 direct.txt > ranges.txt
```

Например, для трёх входных строк, показанных выше, точный вывод `-r -q`:

```text
192.168.1.0-192.168.1.191
192.168.1.200-192.168.1.220
```

С флагами `-r -p 5 -q` вывод станет таким:

```text
192.168.1.0-192.168.1.220
```

Исходный набор содержит 213 адресов. Объединение заполняет промежуток из восьми
адресов, добавляя примерно `3.76%` - меньше разрешённых `5%`.

В режиме диапазонов программа сначала находит непересекающиеся интервалы, затем
по возрастанию заполняет промежутки между ними. Каждый закрытый промежуток убирает
одну запись, поэтому при заданном бюджете число выходных диапазонов минимально.

Через stdin:

```sh
cat direct.txt | ./build/release/cidr-squash -r -p 0.01 > ranges.txt
```

Оптимизированный список всегда выводится в stdout, статистика - в stderr.
Отключить статистику можно через `-q`. После установки пакета на Arch Linux команда
`cidr-squash` доступна в `PATH`.

### Тесты

После сборки пресета `release`:

```sh
python3 -m unittest discover -s tests -v
```

Тесты используют только стандартную библиотеку Python (включая `unittest`,
`ipaddress` и `decimal`), дополнительные пакеты через `pip` не нужны.

В наборе 35 тестовых методов, включая сотни детерминированных случайных
сценариев с фиксированными seed:

- Точные CIDR сверяются с независимым эталоном на `ipaddress`.
- Приближённые CIDR проверяются на сохранение всех исходных IP и соблюдение `-p`.
- Диапазоны проверяются на минимальное число записей в заданном бюджете,
  в том числе полным перебором комбинаций разрывов для небольших случаев.
- Проверяются смешанный ввод, пересечения, дубликаты, перестановки,
  повторная обработка вывода и граничные адреса `0.0.0.0`/`255.255.255.255`.
- Тестируются stdin, файлы, `-q`, `--help`, диагностические сообщения и ошибки CLI.
- Большие подсети проверяются интервалами без перечисления всех IPv4-адресов.

Тесты автоматически запускаются в `check()` при сборке пакета через `makepkg -si`.
Чтобы отдельно проверить другой бинарник, можно задать `CIDR_SQUASH_BIN`:

```sh
CIDR_SQUASH_BIN="$PWD/build/debug-asan/cidr-squash" \
    python3 -m unittest discover -s tests -v
```

## Что означает over-coverage

**Проверяемый контракт:** `-p PERCENT` задаёт максимально допустимый избыток
в процентах от количества различных IPv4-адресов во входном объединении,
а не от количества строк или выходных CIDR. Бюджет дополнительных адресов
округляется вниз до целого и ограничивается свободным адресным пространством
IPv4. И режим CIDR, и `--ranges` сохраняют все входные адреса. Некорректная
входная строка вызывает сообщение с номером строки в stderr и ненулевой код
завершения. Пустой ввод не считается ошибкой: программа завершает работу
с кодом `0`, ничего не выводя в stdout.

При `-p 0` программа строит точное покрытие исходного множества IPv4-адресов:
CIDR или диапазонами в зависимости от флага `-r`. При положительном `-p` разрешено
дополнительно покрыть адреса, которых не было во входном наборе, в обмен на более
компактный результат. Программа никогда не исключает исходные адреса.

Например, `-p 0.01` ограничивает число дополнительных адресов бюджетом примерно
`0.01%` от количества IPv4-адресов, покрытых точным результатом.

Пример статистики:

```text
input entries:       76411
merged intervals:    20975
exact CIDRs:         33256
output CIDRs:        20652
exact IPv4 covered:  985251381
extra IPv4 covered:  98516
over-coverage:       0.00999907%
budget:              98525 IPv4 (0.01000000%)
trie nodes:          132813
```
